# 北北计算器架构审查与分层改造方案

审查日期：2026-09-15

目标：在不推倒重写计算器的前提下，明确触摸/按键、手势、语义编辑、计算和显示之间的边界，为长按、连续删除、滑动光标、选区复制和后续功能补齐建立稳定基础。

## 一、现有架构结论

当前项目已经有两个有价值的基础：

- `CnCwMachine` 是核心状态机，Android 视图主要通过 `CnCwUiState` 读取状态。
- 计算能力已经拆出多个引擎，例如标量、复数、矩阵、向量、统计、电子表格和应用模式引擎。

但目前的真实边界如下：

```text
CalculatorView
  ├─ 触摸识别
  ├─ 显示绘制
  ├─ 光标命中测试
  ├─ 长按复制菜单
  ├─ 系统剪贴板适配
  └─ 直接调用 CnCwMachine.dispatch()

CnCwMachine
  ├─ 按键路由和菜单导航
  ├─ 表达式 token 编辑
  ├─ 光标位置
  ├─ 错误/结果/历史状态
  ├─ 计算调度
  ├─ Ans/变量/格式转换
  └─ 应用模式工作流

各数学引擎
  └─ 负责具体计算，但输入协议和显示协议尚未完全统一
```

## 二、Stage 2 后已改善的边界

Stage 2 已完成真机差分验收，以下问题不再作为下一阶段主任务：

- 长按连续输入/删除已经可用；
- 左右滑动和直接点击可移动光标；
- 手机式选区、左右独立抓手和结构化删除已经可用；
- 剪贴板粘贴已进入核心语义解析链，Android 不再逐字符静默丢弃数学符号；
- Ans 可复制，并能在完成计算后展开上一条计算过程用于核查；
- 固定测试签名和覆盖安装链已建立。

因此下一阶段不要继续堆 View 层补丁，而应集中解决剩余的核心结构问题。

## 三、当前最重要的剩余问题

### 1. 光标仍然是 token 下标，不是语义编辑位置

当前核心仍以 `int cursor` 为主，显示区通过 token 和绘制宽度映射触摸位置。这个模型已经足够支撑普通左右移动，但无法自然表达：

- 分数的分子/分母；
- 幂的底数/指数；
- 根号内部；
- 函数参数；
- 上下方向在数学结构中的跳转。

### 2. 选区仍依赖 token 边界兼容层

目前选区已经能保持函数、分数和幂的整体语义，但本质上仍是对 token 范围做吸附。进入真正的结构内部编辑后，选区锚点也需要升级为语义位置。

### 3. 错误、结果、编辑状态仍未形成明确状态类型

`resultShown`、`errorShown`、`tokens`、`cursor` 等字段仍共同决定当前状态。现有行为已通过大量回归测试稳定下来，因此后续重构必须采用兼容式迁移，不能一次性改掉所有状态字段。

### 4. 应用模式输入/结果协议仍不统一

统计、方程、矩阵、向量、表格等模式仍存在不同输入/结果协议。这个问题放到语义编辑器稳定之后处理。

## 四、Stage 3 目标：语义编辑器

目标边界：

```text
Android 输入
    ↓
输入/手势适配
    ↓
SemanticEditor
    ├─ 语义位置
    ├─ 结构化选区
    ├─ 删除/替换
    ├─ 复制/粘贴
    └─ 撤销快照
    ↓
CalculationSession / CnCwMachine 兼容层
    ↓
数学引擎
    ↓
UiState / Renderer
```

语义位置建议逐步引入：

```text
CursorPath(root, childIndex, slot)
```

`slot` 可以表示：普通行、分子、分母、幂底、指数、根号内部、函数参数等。

旧 token 下标继续保留为兼容字段，直到 Android 命中测试、历史和选区全部完成迁移。

## 五、Stage 3 最小开发顺序

### Step 1：语义位置模型

- 新增平台无关的 `CursorPath` / `SemanticPosition`；
- 建立和现有 token index 的双向兼容映射；
- 不改变当前真机交互表现；
- 新增核心回归测试。

### Step 2：分数内部编辑

- 光标可进入分子和分母；
- 左右移动在各自区域内工作；
- 上下可在分子/分母间切换；
- DEL 不拆坏分数模板。

### Step 3：幂、根号、函数

- 可进入指数；
- 可进入根号内部；
- 可进入函数参数；
- 结构之间的左右/上下移动有确定规则。

### Step 4：语义选区与替换

- 选区锚点/焦点改为语义位置；
- 复制、删除、粘贴和替换保持结构完整；
- 保留现有手机式抓手体验。

### Step 5：Android 命中与渲染迁移

- 触摸命中不再只靠字符串宽度和 token 边界；
- 自然表达式节点提供可点击/可进入区域；
- 真机复验左右滑动、点击、拖选、复制粘贴。

## 六、Stage 3 完成后的下一阶段

语义编辑器稳定后，再统一应用模式结果协议：

- 统计
- 方程/不等式
- 矩阵/向量
- 函数表
- 电子表格/其他模式

统一成功、错误、主结果、可继续编辑内容和 Ans 更新协议，再逐项完善专用界面。

## 七、明确不做的事

- 不为了品牌重命名修改包名、固定签名或核心 profile；
- 不把所有按键改成 Android 原生 Button；
- 不以字符下标替代 token 下标作为最终光标方案；
- 不在 Stage 3 同时大规模重写计算公式；
- 不为了结构重构破坏 Stage 2 已经真机通过的交互。

## 八、阶段完成标准

Stage 3 至少满足：

- [ ] 有独立语义位置类型；
- [ ] 分数分子/分母可进入和上下切换；
- [ ] 幂指数、根号内部、函数参数可进入；
- [ ] 结构化选区/DEL/替换基于语义位置；
- [ ] 旧 token index 兼容层仍可工作；
- [ ] AC、Ans、历史、复制粘贴、长按重复均无回归；
- [ ] 完整核心回归和真机交互验收通过。
